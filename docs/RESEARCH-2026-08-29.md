This file records dated external evidence and rationale. It is **not Product or design authority merely by existing**. Canonical repository contracts are `HOMEPAGE.md`, `DESIGN.md`, `MOTION.md`, `ARCHITECTURE.md`, and `VERIFICATION.md`.

## 1. AI-native frontend workflow

### OpenAI: idea -> visual direction -> Codex -> browser

OpenAI's current Codex use-case guidance describes a concept-first workflow for web/front-end prototypes:

- use ImageGen to generate UI mockups/visual variants before implementation;
- once a direction is selected, have Codex implement the selected visual;
- for direct implementation, OpenAI recommends starting a fresh Codex chat and attaching the final selected image because Codex performs better when it can reference the user attachment;
- use Playwright to open the running app in a real browser and verify each small UI adjustment.

Source:
- https://learn.chatgpt.com/use-cases/idea-to-proof-of-concept

Implication for Lunowa:

`research -> visual variants -> selected oracle -> Codex implementation -> browser verification` is preferable to one-shot prompt-to-site generation.

### OpenAI frontend prompt guidance

Current OpenAI frontend guidance emphasizes:

- real visual assets/product subject instead of generic atmospheric decoration;
- desktop/mobile Playwright screenshot verification before finishing;
- avoiding card-inside-card and turning page sections into floating cards;
- avoiding decorative gradient orbs/bokeh blobs;
- explicit checks for text overflow/overlap and stable responsive dimensions.

Source:
- https://developers.openai.com/api/docs/guides/frontend-prompt

Implication:

Taste should be encoded as explicit constraints and verified in browser, not left to generative defaults.

## 2. Static-first architecture

### Astro Islands

Astro's current documentation states that UI components render to HTML/CSS by default with client-side JavaScript removed unless a `client:*` directive explicitly hydrates an interactive island. `client:visible` can defer hydration until a component enters the viewport.

Sources:
- https://docs.astro.build/ja/concepts/islands/

Implication:

For a marketing site whose body is mostly static content but whose Product demo needs React/Motion, Astro Islands provide a strong fit: static-by-default with targeted JavaScript.

## 3. Cloudflare hosting direction

Cloudflare's current Workers best-practice guidance explicitly says:

> Use Workers Static Assets for new projects.

Pages continues to work, but new features and optimizations are focused on Workers.

Sources:
- https://developers.cloudflare.com/workers/best-practices/workers-best-practices/
- https://developers.cloudflare.com/workers/static-assets/get-started/
- https://developers.cloudflare.com/workers/static-assets/migration-guides/migrate-from-pages/

Implication:

New Lunowa marketing-site deployment should target Workers Static Assets rather than starting on Pages.

## 4. Browser / regression verification

Playwright supports:

- visual screenshot comparison;
- ARIA/accessibility-tree snapshot testing;
- browser-level interaction verification.

Sources:
- https://playwright.dev/docs/test-snapshots
- https://playwright.dev/docs/aria-snapshots

Implication:

Visual and semantic browser state can become durable regression oracles after the initial design is accepted.

## 5. Motion accessibility

W3C WCAG 2.2 Technique C39 documents `prefers-reduced-motion` as a way to prevent non-essential motion for users who request reduced motion. W3C notes that motion can cause distraction or nausea for some users.

Sources:
- https://www.w3.org/WAI/WCAG22/Techniques/css/C39.html
- https://www.w3.org/WAI/WCAG22/Understanding/animation-from-interactions.html

Implication:

Reduced-motion behavior is an acceptance path, not optional polish.

## 6. High-end product design direction

Linear's March 2026 UI refresh explicitly describes a `calmer, more consistent interface`, with supporting navigation receding so task-relevant content takes visual priority. Linear also describes using coding agents to prototype multiple directions quickly and then invest in the selected direction.

Sources:
- https://linear.app/changelog/2026-03-12-ui-refresh
- https://linear.app/now/behind-the-latest-design-refresh

Implication:

For Lunowa, premium quality should come from hierarchy, pruning, consistency, and a few meaningful state transitions rather than maximal visual effects.

## 7. Current synthesis

The evidence above supports this workflow and implementation stance:

```text
Product truth / research
-> IA + copy
-> visual variants
-> select visual oracle
-> static-first implementation
-> targeted React/Motion Product islands
-> real-browser comparison
-> visual + ARIA + interaction regression
-> accessibility/performance/security audit
-> independent full acceptance audit
```

This evidence checkpoint should be refreshed before major architecture/tooling changes; it does not freeze vendor versions indefinitely.
